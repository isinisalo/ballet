# Conformance review

1. Read the initiative BRIEF/PLAN and referenced QS/ADR/CON/BB/RT/DEP IDs.
2. Inspect the actual diff and relevant tests; sample critical source when the change is broad.
3. Classify each mismatch as intended architecture update, implementation defect, documentation drift, risk/debt or an Open question.
4. Cite exact files, stable IDs and evidence. Do not treat provider prose as control evidence.
5. Do not modify the implementation while acting as Validation. Request local retry or capability repair with a measurable expected correction.
6. Record acceptance/conformance evidence and remaining limitations in initiative EVIDENCE/REVIEW.
